The progression

Five states, in order

Every level exists to move you from one of these states to the next. If a lesson does not advance you along this line, it was cut.

01
I know the syntax
You can read Python and predict what it does — including the surprising parts.
02
I write clean Python
Your code reads as idiomatic because every idiom is a choice you can defend.
03
I build applications
Packaging, errors, tests, I/O — the machinery around the logic.
04
I understand trade-offs
Internals, performance and concurrency, so your decisions have evidence behind them.
05
I run it in production
Observable, deployable, debuggable at 3am by someone who is not you.
How each lesson is built

A consistent teaching structure

Not every lesson uses every element — but the ones it uses always mean the same thing, so you learn to read the course as quickly as you read the code.

01
Mental model first
A picture of how the thing works before any syntax, because syntax you cannot model is syntax you will misuse.
02
Realistic examples
Code that resembles the systems you work on. `foo` and `bar` appear only where the point is genuinely abstract.
03
Bad → Better → Production
The same problem solved three times, with the reasoning that separates each rung made explicit.
04
Traps and trade-offs
The mistakes experienced developers still make, and the decisions that have no single right answer.
05
Practice before answers
Exercises with solutions you must deliberately reveal, plus knowledge checks that explain the reasoning.
06
Interview lens
What this topic sounds like when an interviewer probes it, and what separates a strong answer from a recited one.
