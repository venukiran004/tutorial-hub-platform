The model is accurate. That was the easy half.

Ordinary software breaks when someone changes the code. An ML system breaks when the world changes, and nothing in your repository records that the world is an input. So this course is about the half of the job that starts after the notebook: tracking what produced a model, versioning the data as well as the code, serving it behind an endpoint that can be rolled back, and watching the four things that can silently go wrong. Phase 5 is the heart of it — seven incident classes, each taken apart with its own diagnosis path: drift, latency, training-serving skew, scaling failures, lost reproducibility, blind observability and experiments that prove nothing. The drift statistics, the latency percentiles, the skew bugs and the experiment arithmetic are all measured on this machine, which is how the course can tell you that two standard drift detectors disagree about the same shift. Where a tool needs a cluster or an account that is not reachable here — Kubernetes, Terraform, the cloud platforms — the lesson says so and shows the interface rather than pretending to a result.

The progression

Five states, in order

Every module moves you from one of these states to the next. Most teams are somewhere around the second — the model is served and nobody can say what it is doing.

01
I can reproduce it
Every model traces back to a data snapshot, a commit and an environment. Experiment tracking, content-addressed data versioning, and the three hashes an artifact has to carry.
02
I can ship it
Behind an endpoint, in a container, on a scheduler, through a pipeline that gates on model quality rather than only on tests — with a rollback that is one command.
03
I can see it
The right metric type for each signal, a percentile computed honestly, a prediction log that makes drift and skew computable after the fact, and alerts that fire on harm rather than on CPU.
04
I can diagnose it
Seven incident classes with their symptoms and their confirming measurements: which distribution moved, whether the tail is a cold start or a queue, which of the four skews it is, and what to roll back.
05
I can operate an LLM system
Prompts and indexes as versioned deployables, an eval gate that can block a release, token cost as an SLI, and a provider you do not control treated as the dependency it is.
