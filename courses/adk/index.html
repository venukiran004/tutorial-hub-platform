Agents, as a runtime rather than a prompt.

Google's Agent Development Kit is not a wrapper around a chat completion: it is a runtime with sessions, events, state, artifacts, callbacks, a tool contract and two interoperability protocols. This course takes it apart in that order — the four objects everything is built from, agents and the models behind them, tools in depth, the state–memory–context triangle, the control hooks, retrieval, MCP and A2A, then safety, streaming, observability, evaluation and deployment. Every API here was introspected from the installed package and every event trace was produced by running the code against a scripted model, so the traces are the real framework's — no API key required to follow along.

The progression

Five states, in order

Every module exists to move you from one of these states to the next. Most agent projects stall between the third and the fourth.

01
I can run an agent
An agent with a tool, a runner, a session and an event stream you can read — and you can say which object did what.
02
I can make it reliable
Tools the model calls correctly because their declarations are right, state in the correct scope, and errors that return as data rather than end an invocation.
03
I can compose several
Sequential, parallel and loop workflows; a coordinator that routes to specialists; agents as tools; and state passed between them deliberately.
04
I can make it safe and observable
Guardrail callbacks on input and output, a human approval step on the dangerous tool, a trace showing every model and tool call, and an evalset that fails in CI.
05
I can ship it
Persistent sessions, memory across conversations, MCP and A2A for everything you did not write, and a deployment on Cloud Run or Agent Engine with the cost understood.
